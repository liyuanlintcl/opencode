# Omni Specs — 企业级 SDD 规范开发平台实施计划

> 基于已审批通过的《需求文档》和《设计文档》，制定分阶段实施计划，明确任务分工、依赖关系与验收节点。

---

## 1. 项目里程碑

```
M1 基础设施与框架搭建      ──────►  第 1-2 周
M2 需求域 + 审批流上线      ──────►  第 3-4 周
M3 设计域 + 任务域上线      ──────►  第 5-6 周
M4 钩子系统 + 测试域上线    ──────►  第 7-8 周
M5 集成测试 + 性能优化      ──────►  第 9-10 周
M6 正式上线 + 文档交付      ──────►  第 11-12 周
```

---

## 2. 阶段详细计划

## 5. 风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| LLM 解析准确率不达标（< 85%） | 需求结构化质量差 | 中 | 预留 1 周时间做 Prompt 迭代；准备人工兜底流程 |
| Git Hook 对大型仓库性能差 | 开发者体验差 | 中 | T5.3 预留性能优化时间；可配置为服务端 Hook 减轻客户端压力 |
| 前端后端接口不同步 | 联调阻塞 | 高 | 先定义 OpenAPI 契约，前后端按契约并行开发 |
| SQLite 并发性能瓶颈 | 高并发场景崩溃 | 低 | Phase 5 预留迁移到 PostgreSQL 的窗口（设计时已抽象 Repository 层） |
